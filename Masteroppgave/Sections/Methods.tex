\section{Method}
\subsection{Empirical evaluation strategy}

The goal of this chapter is to address the third research objective of the thesis: to evaluate perturbation-based learning methods empirically. This is necessary because neural network optimization problems are generally high-dimensional and non-convex, and the behaviour of a learning rule depends on more than its expected update or estimator variance in isolation. Although the theoretical analysis in Chapter~\ref{ch:original_theoretical_contribution} gives useful predictions about the relationship between WP and IS-NP, and motivates why IS-NP may be better scaled than vanilla NP and fan-in-scaled NP, these results do not by themselves determine practical learning performance. A variance reduction result can be mathematically correct while still having limited practical effect if other factors dominate the optimization dynamics. Similarly, the argument that IS-NP is better scaled than vanilla or fan-in-scaled NP is theoretically motivated, but it is not a proof that IS-NP will train better in all tasks. To understand their practical usefulness, the methods must therefore be tested empirically. The evaluation is divided into two related parts.

The first part asks how well perturbation-based learning methods work in practice as alternatives to backpropagation. Backpropagation is included as the standard reference method because it computes the exact gradient that the perturbation methods attempt to estimate. The goal is not to show that perturbation methods outperform backpropagation, but to understand how close they can get, how difficult a task they can solve, and where their performance begins to break down. Therefore, worse performance than backpropagation should not be interpreted as a failure of the empirical evaluation. It is an expected and informative part of the comparison, because it shows the practical cost of replacing exact gradient computation with stochastic perturbation-based estimates. This is important in relation to the motivation of Chapter~\ref{ch:introduction}: if backpropagation is difficult or impossible to use in biologically inspired architectures or other constrained settings, it is useful to know how capable perturbation-based learning methods are as substitutes.

The second part asks whether the proposed input-scaled node perturbation method improves over existing perturbation methods in the way suggested by the theoretical contribution in Chapter~\ref{ch:original_theoretical_contribution}. In particular, the experiments compare IS-NP with WP, vanilla NP, and fan-in-scaled NP. The comparison with WP tests whether the variance reduction theorem has practical consequences for learning performance and estimator quality. The comparison with the other NP variants tests whether scaling perturbations by the actual incoming activation norm improves over fixed or layer-width-based perturbation scales.

To answer these questions, the methods are evaluated on four supervised learning problems of increasing complexity: synthetic sinus regression, California housing regression, MNIST classification, and CIFAR-10 classification. This progression is chosen so that the experiments can show not only whether a method works, but also how its performance changes as the learning problem becomes more difficult. Simple tasks reveal whether the methods can learn under favourable conditions, while harder tasks make the differences between learning rules more visible. The purpose of including difficult tasks is both to clearly reveal differences between methods and to identify where the perturbation methods become inefficient, unstable, or unable to match the reference performance of backpropagation. The natural next question is therefore: what does it mean for a learning method to work well?

\subsection{Learning problems and datasets}

The empirical evaluation uses four supervised learning problems of increasing complexity. Three of these are standard datasets commonly used in machine learning experiments: California housing, MNIST, and CIFAR-10. The fourth is a synthetic sinus regression task generated specifically to provide a simple and controlled nonlinear regression problem. Together, these tasks span low-dimensional synthetic regression, real tabular regression, simple image classification, and more difficult image classification. The purpose is not to maximize benchmark performance on any one dataset, but to compare how the learning rules behave as the problem becomes more challenging.

The preprocessing is kept simple and standard. The imported datasets are used in their usual form, with only the transformations needed to make them suitable for the fully connected models used in the experiments. This includes standardization for the tabular regression task and pixel scaling, mean-centering, flattening, and one-hot label encoding for the image classification tasks. The following sections describe each learning problem before summarizing the dataset properties in Table~\ref{tab:learning_problem_setup}.


\subsubsection{Synthetic sinus regression}

The sinus task is a synthetic regression problem designed to provide a controlled nonlinear learning problem. The input is an eight-dimensional vector, and the target is generated from a smooth nonlinear function containing sinusoidal terms, quadratic terms, and a small interaction term. This makes the task more interesting than a linear regression problem while still being simple enough that all learning methods should be expected to make progress.

The dataset consists of 512 training examples and 512 test examples. The task is a scalar regression problem, so each input vector is mapped to one real-valued output. The training inputs are sampled uniformly from \([-1,1]^8\). Training targets are corrupted with additive Gaussian noise with standard deviation \(0.1\), while the test targets are generated from the noiseless target function.

No external preprocessing is applied to the sinus inputs in the main experiment. The model receives the sampled input vector directly, so the input values remain in the range \([-1,1]\).

\subsubsection{California housing regression}

The California housing task is a real tabular regression problem. The goal is to predict median house value from housing and geographical features describing districts in California. Compared with the sinus task, this is a less controlled problem because the data come from a real dataset rather than a generated function, but it remains low-dimensional and is therefore a useful intermediate regression task.

The dataset contains 20,640 examples. It is split into 16,512 training examples and 4,128 test examples, corresponding to an 80/20 train-test split. Each input has eight features, and the output is one real-valued target, so the task is scalar regression.

The input features are standardized using the mean and standard deviation computed from the training split. The target values are standardized in the same way. The test set is transformed using the training-split statistics, so no information from the test set is used during preprocessing.

\subsubsection{MNIST classification}

MNIST is a handwritten digit classification task. Each example is a grayscale image of a digit from 0 to 9, and the goal is to assign the image to the correct digit class. The task is substantially higher-dimensional than the two regression tasks, but the images are simple and centered, making MNIST a standard first benchmark for image classification methods.

The full MNIST dataset contains 60,000 training images and 10,000 test images. In this thesis, a subset of 20,000 training examples and 5,000 test examples is used. Because the results were already clear when using 20,000 training examples, this subset size was kept in order to reduce computational cost. Each image has size \(28\times28\), which gives 784 input values after flattening. The output is a 10-dimensional vector corresponding to the ten digit classes, and the task is classification.

Pixel values are scaled to \([0,1]\), mean-centered using the scalar mean of the training subset, and flattened into vectors. The class labels are converted to one-hot vectors for training.

\subsubsection{CIFAR-10 classification}

CIFAR-10 is an image classification task with ten object classes. Each example is a small colour image, and the goal is to assign the image to the correct class. Compared with MNIST, CIFAR-10 is substantially more difficult because the images contain colour, background variation, and more complex visual structure. It is therefore included as the hardest task in the empirical evaluation.

The full CIFAR-10 dataset contains 50,000 training images and 10,000 test images. In this thesis, a subset of 20,000 training examples and 5,000 test examples is used. As for MNIST, because the results were already clear when using 20,000 training examples, this subset size was kept in order to reduce computational cost. Each image has size \(32\times32\) with three colour channels, giving 3072 input values after flattening. The output is a 10-dimensional vector corresponding to the ten classes, and the task is classification.

Pixel values are scaled to \([0,1]\), mean-centered using the scalar mean of the training subset, rearranged to channel-first format, and flattened into vectors. The class labels are converted to one-hot vectors for training.

\subsubsection{Scaled-input diagnostics}

In addition to the four main learning problems, a scaled-input diagnostic experiment is performed on the sinus task. In the main sinus experiment, inputs lie in \([-1,1]^8\). In the scaled-input version, the same underlying target function is used, but the model input is multiplied by \(5\), giving inputs in \([-5,5]^8\). The target values are not changed. This isolates the effect of increasing the input norm while keeping the learning problem itself otherwise fixed.

The purpose of this diagnostic is to test how sensitive the perturbation estimators are to changes in activation scale. Vanilla NP uses a fixed node perturbation scale, while fan-in NP scales only by layer width. Both methods therefore ignore the actual norm of the incoming activation vector. IS-NP, in contrast, scales the perturbation using the incoming activation norm, and WP naturally produces pre-activation perturbations whose scale depends on the input. The scaled sinus setting is artificial in the sense that one would normally avoid unnecessary input rescaling, but it provides a clean way to test what happens when the scale assumptions behind fixed or layer-width-based node perturbation are violated.

This is especially useful because the sinus architecture uses equal hidden-layer widths, so the diagnostic is not confounded by different layer sizes. The experiment therefore focuses directly on the effect of input scale. The same kind of scale mismatch could also occur inside deeper networks if activation norms vary strongly across layers or samples, but the sinus diagnostic makes the effect visible in a simple controlled setting.

\subsection{Model architecture and initialization}

All experiments use fully connected multilayer perceptrons (MLPs). This choice is made to keep the empirical evaluation aligned with the theoretical setting considered in the thesis and to isolate differences between learning rules rather than differences between architectures. For image classification tasks such as MNIST and CIFAR-10, convolutional networks would normally be a more appropriate architecture and would likely give better absolute performance. However, the goal here is not to maximize benchmark accuracy, but to compare perturbation-based learning rules under a common model class. This is also consistent with much of the perturbation-learning literature, where fully connected networks are commonly used to study the behaviour of the learning rule itself. The hidden-layer activation function is sigmoid for the two regression tasks and ReLU for the two classification tasks, while all output layers are linear. The specific layer sizes used for each task are shown in Table~\ref{tab:model_architectures}. All layers are implemented as PyTorch \texttt{nn.Linear} layers with bias terms. Since no custom initialization is applied, the weights and biases use the default PyTorch initialization for linear layers, which is Kaiming-uniform-style for the weights with fan-in-dependent uniform initialization for the biases.

\subsection{Algorithms}

The perturbation estimators used in the experiments are the same score-function-style estimators derived in Chapters~\ref{ch:theory} and~\ref{ch:original_theoretical_contribution}. This section therefore does not rederive the learning rules, but specifies the implementation choices used in the empirical evaluation. These choices are important because they determine how the theoretical estimators are turned into practical mini-batch training algorithms.

All learning methods are trained using mini-batches. The task-specific mini-batch sizes are given in Table~\ref{tab:task_training_protocol}. For backpropagation, this is the standard mini-batch SGD update: the MSE loss is averaged over the mini-batch, the gradient is computed by backpropagation, and the parameters are updated with SGD. No momentum, Adam, weight decay, or learning-rate schedule is used. Backpropagation is therefore not listed as a separate algorithm below, since it is the standard SGD implementation of the gradient computation described in Chapter~\ref{ch:theory}. It is included only as the reference method against which the perturbation methods are compared.

For the perturbation methods, independent perturbations are sampled for each example in the mini-batch. Thus, each example produces its own noisy forward pass and its own scalar loss. The parameter update is then obtained by averaging the resulting per-example update estimates across the mini-batch. Sampling independent perturbations per example is important because the batch-mean baseline relies on variation between perturbations inside the same mini-batch. If the same perturbation were shared by the whole batch, subtracting the batch mean would remove the useful scalar learning signal.

Let \(\mathcal{B}=\{(x_i,y_i)\}_{i=1}^m\) denote a mini-batch of size \(m\), and let \(\ell_i\) be the noisy loss obtained for example \(i\). The scalar learning signal used for each example is
\[
    r_i
    =
    \bar{\ell}_{\mathcal{B}}-\ell_i,
    \qquad
    \bar{\ell}_{\mathcal{B}}
    =
    \frac{1}{m}\sum_{j=1}^m \ell_j .
\]
Thus, perturbations that lead to lower-than-average loss receive a positive learning signal, while perturbations that lead to higher-than-average loss are reversed.

In the theoretical derivation, an independent baseline is required for the usual unbiasedness argument. A leave-one-out mini-batch baseline,
\[
    \bar{\ell}_{-i}
    =
    \frac{1}{m-1}\sum_{j\neq i}\ell_j,
\]
would satisfy this condition because the baseline for example \(i\) would not include the noisy loss generated by the perturbation of that same example. In the implementation, however, the full mini-batch mean \(\bar{\ell}_{\mathcal{B}}\) is used instead. This means that the baseline is not strictly independent of the perturbation for example \(i\), so the estimator is not exactly the same unbiased estimator as the leave-one-out version. This choice is made for computational reasons: the full batch mean is obtained directly from the losses already computed in the noisy forward pass, while a leave-one-out baseline would require a separate baseline value for every example in the mini-batch. Since the self-inclusion effect is of order \(1/m\), it is expected to be small for the batch sizes used in the experiments, and the practical benefit of avoiding the additional computation is considered to outweigh this small approximation.

\begin{algorithm}[htbp]
\caption{Weight perturbation (WP)}
\label{alg:wp_training}
\begin{algorithmic}[1]
\Require Training set \(\mathcal{D}\), model parameters \(\{W_k,b_k\}_{k=1}^{L}\), epochs \(E\), mini-batch size \(B\), learning rate \(\eta\), noise scale \(\sigma\)
\For{\(e=1,\ldots,E\)}
    \For{mini-batch \(\mathcal{B}\subset\mathcal{D}\)}
        \State \(m \gets |\mathcal{B}|\)
        \For{sample \(i=1,\ldots,m\)}
            \State \(a_{0,i}\gets x_i\)
            \For{layer \(k=1,\ldots,L\)}
                \State Draw \(\xi^W_{k,i}\sim\mathcal{N}(0,I)\), \(\xi^b_{k,i}\sim\mathcal{N}(0,I)\)
                \State \(z_{k,i}\gets (W_k+\sigma\xi^W_{k,i})a_{k-1,i}+b_k+\sigma\xi^b_{k,i}\)
                \State \(a_{k,i}\gets \phi_k(z_{k,i})\)
            \EndFor
            \State \(\ell_i\gets \mathcal{L}(a_{L,i},y_i)\)
        \EndFor
        \State \(r_i\gets \frac{1}{m}\sum_{j=1}^{m}\ell_j-\ell_i\) for all \(i\)
        \For{layer \(k=1,\ldots,L\)}
            \State \(\Delta W_k\gets \frac{1}{m}\sum_{i=1}^{m} r_i \xi^W_{k,i}/(\sigma+\epsilon_{\mathrm{num}})\)
            \State \(\Delta b_k\gets \frac{1}{m}\sum_{i=1}^{m} r_i \xi^b_{k,i}/(\sigma+\epsilon_{\mathrm{num}})\)
            \State \(W_k\gets W_k+\eta\Delta W_k,\quad b_k\gets b_k+\eta\Delta b_k\)
        \EndFor
    \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Evaluation metrics}
\label{sec:evaluation_metrics}

In supervised machine learning, the central question is how well a trained model performs on unseen data. The most important empirical quantity is therefore the test loss, since this measures whether the learned function generalizes beyond the examples used for optimization. Training loss is also important, because it shows whether the learning rule is able to reduce the objective on the data it is trained on. These two quantities therefore form the main performance measures in the empirical evaluation.

However, training and test loss provide limited diagnostic information. They show how well a method works, but not why it works or fails. A perturbation-based method may perform poorly because its estimated updates are poorly aligned with the true descent direction, or because the estimates fluctuate strongly between perturbation samples. To better understand the learning curves, we therefore also measure directional alignment and estimator variance. These are natural diagnostics for perturbation-based learning, and they are especially relevant in this thesis because they connect directly to the theoretical results in Chapter~\ref{ch:original_theoretical_contribution}: the expectation-matching result concerns the average update direction, while the variance theorem predicts a difference in estimator variability. The following sections describe the three metric groups used in the experiments, why they matter, and how they are measured in this thesis.

\subsubsection{Training and test performance}

Training and test performance measure how well the learning rule solves the supervised learning problem. Training loss shows whether the method can reduce the objective on the data used for optimization, while test loss measures whether the learned model generalizes to unseen data. These are the most important metrics in the empirical evaluation, since minimizing the loss and obtaining good test performance is the central goal of training the network.

In all experiments, the loss is the mean squared error (MSE) between the network prediction and the target. For the regression tasks, this is simply the squared difference between the predicted scalar output and the scalar target, averaged over examples. For the classification tasks, the class labels are represented as one-hot vectors, and the MSE is computed between the 10-dimensional network output and the one-hot target vector. Classification performance is also evaluated using accuracy, where the predicted class is taken to be the output component with the largest value. The number of training epochs, evaluation batch sizes, and random seeds used for each task are shown in Table~\ref{tab:task_training_protocol}. The loss and accuracy curves are plotted as averages across seeds as functions of training epoch. In addition, the summary tables report the mean \(\pm\) standard deviation across seeds, where each entry is first computed separately for each seed; for example, the reported best test loss is the average of the best test loss reached in each individual seed. The convergence epoch is defined as the first epoch at which the test loss has achieved \(90\%\) of the total improvement from the initial test loss to the best test loss observed during training.

These metrics are interpreted in three main ways. First, the best training and test values show the final performance reached by each method. Second, the convergence epoch indicates how quickly the method approaches its best observed performance. Third, the shape of the learning curves gives information about stability: smooth curves indicate stable learning dynamics, while large fluctuations or spikes suggest that the updates are noisy or unstable. Together, these quantities show not only how well each method performs, but also how efficiently and reliably it learns.

\subsubsection{Directional alignment}

All perturbation-based update rules considered in this thesis are intended to estimate a useful gradient direction from stochastic perturbations and a scalar learning signal. In expectation, these estimators point in the same direction as the gradient of the objective they estimate. This makes it natural to ask how well a finite-sample perturbation estimate aligns with the true gradient in practice. Intuitively, if the estimated update direction is well aligned with the true gradient, the learning rule is likely to reduce the loss efficiently. Conversely, if the estimated gradient frequently points in incorrect directions, learning becomes inefficient and may even increase the loss. A natural way to quantify this alignment is through the cosine similarity between the estimated gradient \(\widehat{g}\) and the true gradient \(g\):
\[
\cos(\widehat{g}, g)
=
\frac{\widehat{g}^{\top}g}{\|\widehat{g}\|\|g\|}.
\]
Here, \(\widehat{g}\) denotes the gradient estimator produced by the learning rule, while \(g=\nabla_\theta L(\theta)\) denotes the true gradient, computed using backpropagation in the experiments. The metric takes values in \([-1,1]\), where \(1\) indicates perfect alignment, \(0\) indicates orthogonality, and negative values indicate that the estimated update direction points against the true descent direction.

The relevance of directional alignment can be seen from a first-order approximation of the loss change. Let \(L(\theta)\) be a differentiable loss function and consider an update
\[
\theta^+ = \theta + \Delta \theta,
\qquad
\Delta \theta = -\eta \widehat{g},
\]
where \(\eta > 0\) is the learning rate. A first-order Taylor expansion around \(\theta\) gives
\[
L(\theta^+) = L(\theta + \Delta \theta)
\approx
L(\theta) + \nabla_\theta L(\theta)^\top \Delta \theta.
\]
Writing \(g=\nabla_\theta L(\theta)\) and substituting \(\Delta \theta=-\eta\widehat{g}\), we obtain
\[
\Delta L
=
L(\theta^+) - L(\theta)
\approx
-\eta g^\top \widehat{g}.
\]
Using
\[
g^\top \widehat{g}
=
\|g\|\|\widehat{g}\|\cos(\widehat{g},g),
\]
this becomes
\[
\Delta L
\approx
-\eta \|g\|\|\widehat{g}\|\cos(\widehat{g},g).
\]
Thus, for fixed gradient norms, a higher cosine similarity gives a larger first-order decrease in the loss. Positive cosine similarity corresponds to a locally descending update, zero cosine similarity gives no first-order improvement, and negative cosine similarity corresponds to local ascent. This makes cosine similarity a useful diagnostic for the directional quality of perturbation-based gradient estimates, although the actual loss change also depends on update magnitude, estimator variance, and curvature.

Concretely, for each task, a model is first trained with backpropagation and saved at three checkpoints representing early, middle, and later training; the checkpoint epochs are given in Table~\ref{tab:task_training_protocol}. Backpropagation is used for this diagnostic so that all perturbation rules are compared at the same parameter values. This makes the comparison between estimators fair: differences in cosine similarity then reflect differences in the update estimates themselves, rather than differences in where each method happens to be during training. Using three checkpoints also tests whether estimator quality changes between the beginning, middle, and later stages of training. At each checkpoint and for each mini-batch in the training set, the reference direction is the exact backpropagation descent direction
\[
    u_{\mathrm{BP}}
    =
    -\nabla_\theta L_{\mathcal{B}}(\theta),
\]
flattened over all weights and biases. For each perturbation method, the same frozen parameters and the same mini-batch are used to compute \(K\) independent gradient estimates. Each estimate is obtained by drawing new random perturbations and applying the corresponding perturbation update rule to the mini-batch, without changing the model parameters. Thus, for method \(m\), this gives \(K\) raw update directions
\[
    \widehat{u}^{(1)}_m,\ldots,\widehat{u}^{(K)}_m .
\]
These are then averaged before computing cosine similarity:
\[
    \bar{u}_m
    =
    \frac{1}{K}
    \sum_{k=1}^{K}
    \widehat{u}^{(k)}_m,
\]
Averaging over \(K\) independent gradient estimates makes the result less dependent on a single lucky or unlucky perturbation draw, and therefore gives a more reliable estimate of the expected update direction. However, increasing \(K\) also increases memory use and computation time. The task-specific values of \(K\), listed as gradient estimates per mini-batch in Table~\ref{tab:task_training_protocol}, are therefore smaller for the larger image models. The update directions are stored before multiplication by the learning rate, so the cosine comparison measures directional quality independently of the learning-rate choice. The batch-level cosine similarity is then computed as
\[
    \cos(\bar{u}_m,u_{\mathrm{BP}})
    =
    \frac{\bar{u}_m^\top u_{\mathrm{BP}}}
    {\|\bar{u}_m\|\|u_{\mathrm{BP}}\|}.
\]
This value is averaged over all mini-batches in one full pass through the training set and over all random seeds, using 10 seeds for the sinus task and 5 seeds for the other tasks because of their higher computational cost. In the main results, the three checkpoint values are also averaged to give one final cosine value per method and dataset. The summary tables report the mean \(\pm\) standard deviation of this aggregate cosine across seeds. The checkpoint-specific cosine values are also saved and plotted separately, but they are moved to the appendix because they do not change the main interpretation and would otherwise add many extra plots to the results chapter.
\subsubsection{Estimator variance}

Directional alignment measures whether a gradient estimator points in a useful direction, but it does not capture how much the estimate fluctuates between perturbation samples. In perturbation-based learning, the gradient estimate is obtained from random perturbations, so two perturbation samples at the same parameter values can produce different update directions. Even if the estimator is well aligned with the true gradient on average, large fluctuations can make learning inefficient. Variance is also central to the theoretical contribution of the thesis, where IS-NP was shown to have lower or equal coordinate-wise variance than WP under the matched perturbation construction. Estimator variance is therefore a natural diagnostic to measure empirically. Before describing how it is measured, we first show how variance affects the expected change in loss.

The relevance of estimator variance can be seen from a second-order approximation of the loss change. Let \(L(\theta)\) be twice differentiable and consider the update
\[
\theta^+ = \theta + \Delta\theta,
\qquad
\Delta\theta = -\eta \widehat{g},
\]
where \(\eta>0\) is the learning rate. A second-order Taylor expansion around \(\theta\) gives
\[
L(\theta^+)
\approx
L(\theta)
+
\nabla_\theta L(\theta)^\top \Delta\theta
+
\frac{1}{2}\Delta\theta^\top H\Delta\theta,
\]
where \(H=\nabla_\theta^2 L(\theta)\) is the Hessian. Writing \(g=\nabla_\theta L(\theta)\) and substituting \(\Delta\theta=-\eta\widehat{g}\), we obtain
\[
\Delta L
=
L(\theta^+) - L(\theta)
\approx
-\eta g^\top \widehat{g}
+
\frac{\eta^2}{2}\widehat{g}^\top H\widehat{g}.
\]

Taking expectation over the stochastic gradient estimator, and assuming \(\mathbb{E}[\widehat{g}]=g\), gives
\[
\mathbb{E}[\Delta L]
\approx
-\eta \|g\|^2
+
\frac{\eta^2}{2}g^\top H g
+
\frac{\eta^2}{2}\operatorname{tr}(H\Sigma).
\]
The important point is that estimator variance appears directly in the expected loss change through the term \(\operatorname{tr}(H\Sigma)\), where \(H\) is the Hessian of the loss with respect to the parameters and \(\Sigma\) is the covariance of the gradient estimator. This means that update noise is not merely random fluctuation around an otherwise good direction; it can directly reduce the expected progress made by an update. In particular, variance is most harmful when it lies in directions where the loss has high curvature, because those directions are weighted more strongly by \(H\). Ideally, we would measure the full curvature-weighted quantity \(\operatorname{tr}(H\Sigma)\), but estimating the Hessian and the full covariance matrix is not practical for the repeated perturbation experiments used here. We therefore measure estimator variance itself as a tractable and directly relevant diagnostic of update noise.


Estimator variance is naturally defined through the covariance matrix of the vector-valued gradient estimator. For a gradient estimator \(\widehat{g}\), this covariance matrix is
\[
    \Sigma
    =
    \mathbb{E}\!\left[
    (\widehat{g}-\mathbb{E}[\widehat{g}])
    (\widehat{g}-\mathbb{E}[\widehat{g}])^\top
    \right].
\]
When the estimator is unbiased for the gradient \(g=\nabla_\theta L(\theta)\), this can be written as
\[
    \Sigma
    =
    \mathbb{E}\!\left[
    (\widehat{g}-g)
    (\widehat{g}-g)^\top
    \right].
\]
This is useful here because the exact gradient can be computed using backpropagation. Instead of estimating variance by subtracting the empirical mean of the perturbation samples, we subtract the exact backpropagation direction. However, \(\Sigma\) is a full covariance matrix over all parameters, which is too large to report directly. We therefore reduce it to a scalar by averaging its diagonal entries. Each diagonal entry is the variance of one parameter update component, corresponding to one weight or bias. The resulting quantity,
\[
    \frac{1}{P}\operatorname{tr}(\Sigma),
\]
is the average variance per parameter.

The measurement procedure follows the same frozen-checkpoint structure as the cosine-similarity calculation, using the diagnostic checkpoints and task-specific values of \(K\) listed in Table~\ref{tab:task_training_protocol}. For each checkpoint, mini-batch, and perturbation method, the exact backpropagation descent direction \(u_{\mathrm{BP}}\) is computed and flattened over all weights and biases. We then draw \(K\) independent perturbation-based gradient estimates,
\[
    \widehat{u}^{(1)}_m,\ldots,\widehat{u}^{(K)}_m,
\]
using the same frozen parameters and the same mini-batch. The empirical estimate for one method, checkpoint, and mini-batch is then
\[
    \widehat{V}_m
    =
    \frac{1}{K}
    \sum_{k=1}^{K}
    \frac{1}{P}
    \left\|
    \widehat{u}^{(k)}_m - u_{\mathrm{BP}}
    \right\|_2^2 .
\]
Here, the factor \(1/P\) averages over parameters, while the factor \(1/K\) averages over independent gradient estimates.

As for cosine similarity, this variance estimate is averaged over all mini-batches in one full pass through the training set and over random seeds, with the number of seeds given in Table~\ref{tab:task_training_protocol}. In the main results, the three checkpoint values are also averaged to give one final variance value per method and dataset. The summary tables report the mean \(\pm\) standard deviation of this aggregate variance across seeds. Checkpoint-specific variance plots are also generated and included in the appendix, while the main results focus on the aggregate variance plots.

\subsection{Hyperparameter selection and experimental protocol}

Hyperparameter tuning is important because each method must be given a fair chance to learn. If tuning is not done carefully, the results may reflect the chosen hyperparameters more than the learning rule itself. If the learning rate or perturbation scale is too small, learning can become unnecessarily slow or the loss differences can become too weak to give useful updates. If they are too large, the updates can become unstable or no longer reflect a useful local learning signal. Since the learning rate and perturbation scale interact in ways that are not always obvious or trivial, fair tuning requires a systematic search.

For each learning problem, the dataset split, preprocessing, network architecture, mini-batch size, and evaluation procedure are held fixed across learning rules. The tuned hyperparameters differ between methods:
\begin{itemize}
    \item \textbf{Backpropagation:} learning rate \(\eta\).
    \item \textbf{Weight perturbation:} learning rate \(\eta\) and perturbation scale \(\sigma\).
    \item \textbf{Vanilla node perturbation:} learning rate \(\eta\) and perturbation scale \(\sigma\).
    \item \textbf{Fan-in-scaled node perturbation:} learning rate \(\eta\) and perturbation scale \(\sigma\).
    \item \textbf{Input-scaled node perturbation:} learning rate \(\eta\) and perturbation scale \(\sigma\).
\end{itemize}
Each method is tuned separately for each task.

The tuning procedure was carried out in two phases. The first phase focused on selecting reasonable perturbation scales. This was done before tuning the learning rate, because the learning rate and perturbation scale interact in ways that can make training curves difficult to interpret. For example, slow learning could be caused by a learning rate that is too small, a perturbation scale that is too small, a perturbation scale that is too large, or some combination of these. To separate these effects as much as possible, we first evaluated candidate \(\sigma\) values using the frozen-estimator diagnostics from Section~\ref{sec:evaluation_metrics}. These diagnostics measure cosine similarity and estimator variance without applying parameter updates, and therefore do not depend on the learning rate. For each task and perturbation method, the search began with a broad set of five candidate \(\sigma\) values. The candidates were evaluated across the three diagnostic checkpoints and averaged. If the results showed a clear trend, for example that larger \(\sigma\) values improved cosine similarity and reduced variance, the range was shifted accordingly. This process was repeated with progressively narrower ranges until three nearby \(\sigma\) values were selected for each method: a central value with the best overall diagnostic trade-off, and one slightly smaller and one slightly larger value. These three values were then used as the perturbation-scale axis in the training grid search.

The second phase combined the selected perturbation scales with learning-rate tuning. For each perturbation method, we chose three initial learning rates based on preliminary runs and practical experience with the learning algorithms, giving a \(3\times3\) grid over learning rate and perturbation scale. The first goal in this phase was to check whether the learning-rate range was sensible. If the training curves generally improved when the learning rate increased, the range was shifted upward; if larger learning rates caused instability or worse final performance, the range was shifted downward. This stage was evaluated using actual training and test curves, with attention to convergence speed, final loss, and stability. Once the learning-rate range appeared reasonable, the full \(3\times3\) grid was inspected and refined. The grid was narrowed until the results were reasonably consistent and did not show a clear monotonic trend toward one edge of the grid, such as consistently better performance at the highest learning rate or largest perturbation scale. The aim was to choose a final setting from the interior of a stable region, rather than from a boundary where further improvement might simply require extending the search range.
